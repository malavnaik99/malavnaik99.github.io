# Something broke? Start here

Plain-English fixes for malavnaik.com. Each problem below comes with what it means and exactly what to do.
When in doubt, open Claude Code on this repo and paste what you see. Claude follows `CLAUDE.md`.

**How you hear about problems:** the **Site health** check runs every Monday at 07:00 (Irish time) and after every change.
If something is wrong it opens a GitHub Issue titled `Site health: …` (GitHub emails you if you **Watch** this repo),
updates it while the problem lasts, and closes it by itself once fixed. Issues: https://github.com/malavnaik99/malavnaik99.github.io/issues

## Regular jobs (the only things that need you)

- **Around the 2nd of each month (2 minutes):** a pull request "Dublin Bikes in numbers: YYYY-MM (draft)" appears. Check the numbers look sensible and **merge** it: /dublin-bikes/ updates within minutes.
  To also publish that month's post: ask Claude "Publish the (month) Dublin Bikes post." (It moves the file from `_drafts/` to `_posts/` with the publish date in front of the name.)
- **After you publish each Dublin Bikes post (10 minutes, when you like):** an issue "Share kit ready: Dublin Bikes <Month YYYY>" opens with a Reddit post, a first comment, an email pitch and a chart, all written from that month's numbers. Nothing is posted for you: copy the texts, post them yourself, tick the boxes and close the issue. After new rent figures (about twice a year) a "Share kit ready: Irish rents …" issue does the same for r/irishpersonalfinance.
- **Living in Ireland review (once, then when an issue asks):** read `REVIEW-living-in-ireland.md`, then tell Claude Code which rows are right ("mark 0/work 2/work verified") and what to fix. A stamp page appears in Google, the sitemap and the Ireland Guides page only after at least one of its rows is marked verified.
- **January:** an issue "Rent tool: update the tax rates" may open. See its row above.
- **Every few weeks (optional):** look at Google Search Console → **Performance** and **Pages**, and share a screenshot with Claude for ideas on what to improve.
- Everything else runs by itself: the rent data refresh (Wednesdays), the site health check (Mondays and after every change), and the hourly bike sky check.

## Roll back a bad change

**Fastest, one step (puts the old version live in about 2 minutes):**
1. Go to **Actions → Deploy site to Pages**.
2. Click the last run with a green ✅ **before** the bad change.
3. Click **Re-run all jobs**. GitHub republishes that older version.

This is temporary: the next change to `main` publishes the newest version again. So then tell Claude:
"Roll back the change called '(commit message)' on main", and it will undo it properly (a *revert* commit, so nothing is lost).

## Where things live (for Claude or a developer)
- Identity (name, title, email, bios, profiles): `identity/identity.json`, the single source of truth. `scripts/check_identity.py` stops a deploy that drifts from it.
- Share kits: `scripts/share_kit.py` writes `share-kits/YYYY-MM/` (not published on the site); `.github/workflows/share-kit.yml` runs it when a Dublin Bikes post is published, and after new rent data (started by the rent refresh). `share-kits/rent-periods-done.txt` lists the CSO periods that already had a rent kit. `blog-bot-post.md` in each kit is the blog bot's copy of the edition; how the bot picks it up: `docs/blog-bot-bikes-editions.md`.
- Living in Ireland: all content is in `_data/stamps.yml` (one row per stamp × topic, plus the Stamp 2 "first 90 days" checklist and the help-box links). Pages: `living-in-ireland/` (hub) and `living-in-ireland/stamp-*/`, built by `_includes/stamp-page.html`; `_includes/stamps-live.html` hides a page from Google/sitemap/llms.txt until a row is reviewed. `scripts/stamps_check.py`: `--self-test` (runs before every deploy: quotes word for word against `data/stamps/snapshots/`, wording rule), `--review` (rewrites `REVIEW-living-in-ireland.md`, not published), `--verify 4/work` (marks a row checked), `--links` and `--content` (run by `.github/workflows/stamps-check.yml`, Mondays and the 1st of the month).
- Main menu: `_layouts/default.html` (the `nav` line). With five items the header folds into the "Menu" button below 881px wide (`assets/site.css`); if you add a sixth item, check a tablet-width screen for the Résumé button wrapping.
- Ireland Guides page (`ireland-guides/index.md`): lists each guide from its `guides:` lines, and shows a guide only once its page exists, so a new guide appears there automatically when its page is published.
- Page head, previews, structured data: `_layouts/default.html`, `_includes/schema.html`, `_config.yml`
- Page titles: written in `_layouts/default.html` (not by jekyll-seo-tag). Home and About show the full `site.title`; every other page is `seo_title` (if set) or `title`, then " | Malav Naik". Keep that under about 60 characters. `scripts/site_health.py` (`title_ok`) checks the same rule on the live site.
- Structured data (`_includes/schema.html`): Person on every page; WebSite on Home; ProfilePage on About; BlogPosting on posts; BreadcrumbList on every page except Home (posts sit under Writing, projects under Work, other pages under their parent folder's page, e.g. /rent/galway/ under /rent/; a page's crumb name is its `breadcrumb:` line, else its title); FAQPage on any page with `faq:` front matter, or `faq_from: <_data file>` whose `faq` list holds the answers (the /rent/ hub uses `faq_from: rent_summary`, written weekly by `scripts/rent_build.py`). Posts and project pages show the same list via `_includes/faq.html`, and a "Sources" list from `sources:` front matter via `_includes/sources.html` (each item: `name`, optional `url`, optional `note`; with no `url` the name shows without a link). Posts show "By Malav Naik · Data & GenAI Engineer, Dublin", "Published" and, only when the file changed later, "Last updated": that date, and BlogPosting `dateModified`, is the post file's last git commit (from `_data/lastmod.json`), never typed by hand; Dataset on any page with `dataset:` front matter (`dataset.creator` names an organisation, otherwise Malav is the creator; its `dateModified` is the CSO's own update date on rent pages, otherwise the page's last change). /dublin-bikes/ writes its own FAQPage block in the page, because its answers come from data.
- Sitemap: `sitemap.xml` (hand-written; the jekyll-sitemap plugin was removed). Every page, posts included, uses the date of its last commit, from `_data/lastmod.json`, which `scripts/lastmod.py` writes during the deploy (needs `fetch-depth: 0` in `static.yml`; the file is not committed). PDFs and images are not listed. `robots.txt` and `llms.txt` (AI assistants' summary, built from identity.json, the latest 6 posts and the key pages) are also in the root.
- Home page "Latest writing": the latest 6 posts (`index.md`). The blog bot's own numbers appear only in the Automation Lab section (`_data/automation.json`).
- Sandboxes and search: `assets/islands/` (one file each, loaded only when needed), data in `assets/data/`. Ctrl+K and the home "Ask" box both use `search.js` over `search.json`.
- Home page projects: the featured Dublin bikes card and the four mixed-colour cards, written in `index.md`.
- Project rows (/work/): `_includes/project-row.html`; each project's row text, headline number, chart and "Try it" link are in its `_projects/*.md` front matter. Charts: `_includes/charts/`, drawn by `scripts/make_charts.py` (automation bars are drawn at build time from `_data/automation.json`).
- Labs (/labs/): the three sandboxes on one page. Each keeps its state in the address (`?t=` threshold, `?q=` question, `?sql=` query) via `window.sandboxState` in `assets/site.js`.
- Home page sky (hero map): `assets/islands/hero-map.js` is the map itself: the projection, the outline lines, the five place labels, the fade under the hero text, and **Explore the live map** (a full-screen `<dialog>` showing the same OpenStreetMap street map as the Dublin bikes project page, `islands.stationmap` in sky.js, built the first time it opens). It opens from the "Explore the live map" button, the underlined "Live map" link at the top of the hero, or the address https://malavnaik.com/#live-map (shareable). `assets/islands/sky.js` adds every station from `assets/data/sky.json` (the saved snapshot `_data/sky.json`, made by `scripts/make_sky.py`) and the 48-hour replay. Timing (to keep Lighthouse at 100): the map starts 2.5 s after the page loads (at once if a visitor presses Explore first), shows the newest hour, and the replay starts 6 s later (`REPLAY_AFTER_MS` in sky.js; never under reduced motion, nor after the visitor uses Play or the slider). The label words are in `index.md` and the dialog's text in `_includes/sky-bar.html`, as plain HTML so the Gujarati (Google Translate) copy translates them. Live data (on since 16 Nov 2026): `_data/sky_live.json` points at `sky/latest.json` in the Hugging Face dataset `Malavnaik/dublin-bikes-weather-marts`. The `dublin-data-pipeline` repo rebuilds it every hour (`transform.py` → `sky()`, run by its Transform workflow, which the collector starts at :15 past each hour); it leaves out STATION118 and stations reporting 0 docks (Parnell Square North). The page uses it while it is under two hours old, otherwise the saved snapshot; the page itself also drops 0-dock and placeholder stations. Format: `docs/pipeline-latest-json.md`. To switch live data off, empty that `url`. Hourly freshness check: `.github/workflows/sky-freshness.yml` → `site_health.py --only "Bike sky data is old"`.
- Receipts (the four numbers under the hero): click a number to see its dataset, file and test. Text lives in the Receipts table of `docs/METRIC_SOURCES.md`; `scripts/make_receipts.py` copies it to `_data/receipts.json`; the deploy checks they match.
- Hero map outlines (Dublin Bay coast, River Liffey, Grand Canal, Royal Canal, Phoenix Park) and label positions: `assets/data/dublin-outlines.json`, a static file from OpenStreetMap (© OpenStreetMap contributors, ODbL), downloaded once on 16 Nov 2026 and simplified to 20 m; credited under the hero and in explore mode (`_includes/sky-bar.html`). Refresh with `python3 scripts/make_sky.py --outlines` (move a label: edit `LABELS` in that script, then `--labels`). Cloud sessions can't reach overpass-api.de, so run it on GitHub Actions (a one-off workflow, as in git history: "Temporary: download the hero map outlines") or on a computer. The script refuses to save outlines that don't sit where they should beside the stations. The older `_data/sky_river.json` (`--river`) is no longer drawn.
- Street map (Dublin bikes project page, "Station map"): `islands.stationmap` in `assets/islands/sky.js`, same data as the hero sky; Leaflet 1.9.4 is a pinned copy in `assets/vendor/leaflet-1.9.4/` (BSD-2 licence file included); map images from OpenStreetMap (© OpenStreetMap contributors, credited on the map and under it).
- Rent tool (/rent/ and /rent/<county>/): `scripts/rent_build.py` downloads CSO tables RIH02 (rents) and DEA05 (earnings) every Wednesday (`.github/workflows/rent-refresh.yml`), checks them, and writes `data/rent/rents.json` (all rents, plus each county's latest rent by property type under `types`), `data/rent/meta.json`, the 26 county pages and `_data/rent_summary.json`. The /rent/ page builds its intro answers, its first rent card and its sortable county table from that summary, so they show without JavaScript; the interactive tool then takes over. - Dublin Bikes statistics (/dublin-bikes/) and the monthly "Dublin Bikes in numbers" posts: one data file per month in `_data/bikes/YYYY-MM.json`, written by `scripts/bikes_report.py` from the Hugging Face datasets and delivered by the monthly pull request (`.github/workflows/bikes-report.yml`, 2nd of the month). `dublin-bikes/index.html` reads every month's file; each post holds only its intro and `{% include bikes-edition.html month=page.bikes_month %}`, which draws the numbers, tables and previous/next links. The script also keeps the year in the hub's title current (`set_hub_year`). Thousands separators in templates: `_includes/num.html`.

- Backlinks: `backlinks/README.md` (kit), `backlinks/tracker.csv`, `backlinks/ROUTINE.md`
- Fonts: Inter, Inter Tight and JetBrains Mono are served from this site (`assets/fonts/`, licences and versions in its README), declared at the top of `assets/site.css`. No request to Google. If text suddenly looks like Arial everywhere, check those files are still there.
- Page speed: homepage sections below the first screen use `content-visibility: auto` (in `.section`, `assets/site.css`), so the browser skips them until the visitor scrolls near; and `assets/site.js` does its non-urgent set-up one step after the page appears (`setTimeout(rest, 0)`). Both keep Lighthouse near 100. A full-page screenshot tool may show those sections blank: that is the tool, not the site (scroll down in a browser to check).
